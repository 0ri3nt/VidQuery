# VidQuery audit: training status, data coverage, feasibility, and cost

Audit date: 25 October 2026, on branch `audit-honest-evaluation`.
Labels used throughout: **[measured]** means read from code, logs, checkpoint
metadata, or a command run during this audit. **[estimate]** means derived
from measurements with stated assumptions. **[unknown]** means it could not be
verified here; the section says how to check.

## 1. Executive summary

- **Verified end-to-end accuracy is low.** On a new model-only benchmark
  (six held-out AVA windows, 120 queries, 25% negative), held-out P@1 for
  action queries is 0.13-0.20 [measured]. The README's 0.96 is retrieval over
  labelled evidence, and the 0.50 is GNN predictions on one training-cache video.
- **The largest bottleneck is the query parser, not training data.** It missed
  the intended action label on 27 of 45 test queries. Those queries scored
  P@1 0.04; correctly parsed ones scored 0.33 [measured].
- **Learned trust values shift the abstention operating point but do not
  improve confidence ranking.** Negative rejection rises from 0.20 to 0.87, but
  only 24% of answerable queries get an answer. AURC is 0.77 vs 0.72 and AUROC
  0.56 vs 0.51, with overlapping intervals [measured].
- **Both GNNs are small heads on frozen ImageNet ResNet-18 features.** They
  used 10% (AVA) and 1% (VidOR) of the labelled videos. The action model's
  best epoch was epoch 1. Data scaling from 11 to 31 training videos moved test
  mAP by only about 1-2 points [measured].
- **Full AVA v2.2 and full VidOR can be done on the laptop for about ₹0.**
  This needs a slimmer feature-cache format. The current format would need
  about 47 GB peak disk against 30 GB free, and would not fit in RAM. The
  shortfall is about 17 GB [estimate].
- **Fixed in this audit:** the evaluator scored weak answers to negative
  queries as successes. The prior fitter crashed on real source names.
  Phonetic matching for misheard technical terms was added (off by default).
  Tests rose from 191 to 207 passing.

## 2. Architecture and data flow [measured]

The canonical application is `vidquery/` (about 20,000 lines), with the
browser UI in `frontend/`. `extraction/`, `modelling/`, `core/`, `retrieval/`,
`api/`, `app/`, and `main.py` are the legacy AVA research pipeline, still used
by `scripts/process_ava_selection.py`.

Indexing, in `vidquery/pipeline.py`:

1. Upload validation and SHA-256 dedupe.
2. Frames at 1 fps and 16 kHz audio, via imageio-ffmpeg (no system ffmpeg on PATH).
3. YOLOv8n (COCO-80) and short-range IoU tracking.
4. Whisper `tiny` with word timings, then Pyannote 3.1 diarization.
5. EasyOCR, then OpenCLIP ViT-B-32 track embeddings.
6. Box geometry relations, then the VidOR pair-visual GATv2 (50 predicates).
7. Five-second canonical segments, then the AVA GATv2 (80 actions), then MiniLM vectors.
8. Storage in SQLite, with an optional Neo4j mirror.

Search, in `vidquery/search.py`, `reliability.py`, `hypotheses.py`, and
`localization.py`:

1. A rule-based parser builds a plan. Groq is consulted only for ambiguous queries.
2. Hybrid lexical, semantic, entity, action, relation and appearance scoring per segment.
3. Reliability fusion assigns `supported`, `weak` or `insufficient`.
4. Hypotheses handle ambiguous queries; peak localization picks the moment.
5. Abstention fires only when every top result is `insufficient`.

Evaluation lives in `vidquery/evaluation.py` (Review-1, 5-second segment
relevance) and `vidquery/challenge_evaluation.py` (Review-2, point ground
truth, abstention). Calibration uses `scripts/calibrate_reliability.py` and
`scripts/fit_reliability.py`.

## 3. Model-by-model training status

### AVA action GNN `ava80-gat-v5-scale30-roi-frame` (active) [measured]

| Item | Value |
|---|---|
| Architecture | 2-layer GATv2 (hidden 128, dropout 0.2) over 1,162-dim node features: 138 handcrafted plus frozen ResNet-18 ROI and whole-frame embeddings |
| Checkpoint | `data/app/models/ava80_scaling/30/ablations/…roi-frame.pt`, SHA-256 `68e4d54e…`, about 0.95 MB |
| Data | AVA v2.2 train+val CSVs; split 24 train / 3 val / 3 test videos |
| Samples | Graphs 18,401 / 2,245 / 2,554; supervised persons 35,095 / 3,378 / 5,274 |
| Training | AdamW lr 1e-3, batch 32, patience 10; ran 11 epochs; best epoch 1 (validation loss rose every epoch after it) |
| Hardware and time | RTX 4060 Laptop GPU, 145.5 s |
| Validation | Supported macro F1 0.125, mAP 0.109 |
| Test | Supported macro F1 0.072, micro F1 0.462, mAP 0.087 |
| Later candidate | v6 on 37 videos (31 train): validation macro F1 0.125, test mAP 0.080; not activated |

**Coverage against available labelled AVA v2.2** (235 train + 64 val videos,
with 426,346 person boxes in the local CSVs; the 131 test videos have no
public labels):

| Stage | Videos | Share of 299 |
|---|---:|---:|
| Feature-cached and validated (expansion state) | 37 | 12.4% |
| Used by the active model (all splits) | 30 | 10.0% |
| Used for training weights (active) | 24 | 8.0% |
| Raw media still on disk | 17 (+8 unrelated WhatsApp clips) | 5.7% |

Supervised persons used are 43,747 of 426,346 (10.3%). Within a used video,
almost every annotated keyframe was used (about 780 graphs per video).

**Why the expansion stopped:** across 288 recorded batches, 271 download
attempts failed with `curl: (6) Could not resolve host: s3.amazonaws.com`, and
262 videos were left marked as transient failures. This was a DNS or network
outage, not lack of disk; 15.8 GB was free at the stop.

**Issues found:**

- `annotation_only` and `detector_confidence` are input features. Ground-truth
  boxes YOLO missed are added with the flag set to 1 and confidence 0. At
  deployment the flag is always 0. This affects 7.1% of training, 5.0% of
  validation and 2.5% of test supervision, so reported test metrics are
  slightly optimistic.
- Metrics use ground-truth-assisted person boxes: the action-classification
  setting, not AVA detection mAP. Comparisons with 40-46 mAP detection SOTA are
  not like-for-like.

### VidOR relation GNN `vidor-relation-pair-visual-gat-v2` (active) [measured]

| Item | Value |
|---|---|
| Architecture | Pair features (subject, object and union ResNet-18 ROI, class, geometry, motion) plus 2-layer GATv2 |
| Data | VidOR training archive part 1 of 8; 67 videos (57 / 6 / 4), at most 6 frames each |
| Samples | 402 graphs; 11,981 candidate edges (7,900 positive, 4,081 negative) |
| Training | Selected epoch 17 of 24; 8.9 s on the RTX 4060 |
| Validation / test | Supported macro F1 0.308 / 0.178; test micro F1 0.371; test mAP 0.191 |
| Coverage | 67 of 7,000 training videos (0.96%); 402 frames |

**Issues found:**

- The model trains on ground-truth VidOR boxes and classes, but runs on YOLO
  detections mapped to VidOR classes.
- `YOLO_TO_VIDOR` maps COCO `mouse` (a computer mouse) to `hamster/rat`, and
  `potted plant` to `toy`. Both are wrong, and both matter in classrooms.
- VidOR has no `book`, `paper` or `door` class.

### Other models (pretrained, not trained here)

YOLOv8n/s/m, Whisper tiny/small/medium/large-v3-turbo (all four cached),
Pyannote 3.1, EasyOCR, OpenCLIP ViT-B-32, and MiniLM. The legacy
`person_action_classifier` has no valid checkpoint and is replaced by the GNN.

## 5. Full-dataset feasibility

### Action model: full AVA v2.2 (299 labelled videos)

| | Current | Full |
|---|---:|---:|
| Videos | 37 cached, 30 used | 299 (262 to fetch) |
| Raw transfer | | 107-141 GB [estimate: 0.41-0.54 GB/video measured] |
| Feature cache, current format | 50 MB/video plus a 46 MB/video master | about 15 GB plus 13.7 GB master; **peak about 47 GB** during master rebuild, with the 4 GB reserve |
| Feature cache, slim format | | **about 2-3 GB** [estimate: active `visual_x` only, fp16, no per-node frame copies] |
| RAM to train | 1.6 GB master | current format about 14 GB (does not fit); slim about 2-3 GB |
| Processing time | | 9-22 h for 262 videos, network-bound [estimate: 2-5 min/video] |
| Training time | 145 s | 20-120 min [estimate: about 133 s/epoch at 184k graphs, scaled from measured] |
| VRAM | | under 1 GB at batch 32 |

**Disk verdict:** the current format exceeds the 30 GB free by about 17 GB,
and the master cache would not fit in 15.6 GB RAM. The smallest safe change
is to write per-video shards containing only the active feature tensor in
fp16, train from shards, and keep deleting raw media after validation (the
existing behaviour). Peak use is then under 10 GB. An external SSD is not
required.

Training is fine-tuning a tiny head over a frozen backbone, not training from
scratch. Mixed precision, gradient accumulation, and checkpointing are
unnecessary at this size.

**Expected benefit is small** [estimate]. Measured scaling: 11 to 24 training
videos took test mAP from 0.065 to 0.071, and v6 at 31 videos scored 0.080
against v5's 0.087. Eight times more data might add 1-3 mAP points. The
dominant limits are single-frame ImageNet features and immediate overfitting.

A Kinetics-pretrained video backbone would help far more. But any public
AVA-trained checkpoint has seen our test videos, which come from AVA train,
so the benchmark would then need new held-out videos.

### Action model: AVA-Kinetics

- About 238k Kinetics-700 clips, each with one annotated keyframe; CC BY 4.0
  annotations.
- Video comes from the CVDF Kinetics-700-2020 mirror: about 603 GB train
  tars, 710 GB in total.
- Streaming tar by tar keeps peak disk to a few GB. But it is 600+ GB of
  transfer and an estimated 13-33 h of processing.
- It needs a new loader: Kinetics clip IDs, one keyframe per clip, and no
  motion track unless neighbouring frames are extracted.
- It adds diversity, not classroom domain. Defer; it suits a rented GPU if done.

### Relation model: more VidOR (same 50 predicates)

- 7,000 training videos in 8 zip parts; 29.2 GB in total including 3.06 GB
  of validation video; CC BY-SA 4.0.
- `scripts/stage_vidor_pair_visual_frames.py --part N` already range-reads
  single videos from the remote zip and keeps only the needed frames.
- Full coverage is about 26 GB of transfer, 42k frames (2-4 GB), and a
  1.5-3.5 GB graph cache [estimate]. Training takes under 30 min.
- Feasible on the laptop as is. Fix the class-mapping bugs first, and consider
  training on YOLO boxes matched to ground truth, to close the
  training/inference gap.

### Relation model: Action Genome

- Charades 480p videos (16.3 GB per Hugging Face metadata; one mirror lists
  about 70 GB, so verify), plus annotations from Google Drive.
- 234k annotated frames, 35 object classes, 25 relation classes. The code is
  MIT; the Charades data is non-commercial academic only.
- Avoid the documented 74 GB frame dump: extract annotated frames per video
  and cache features instead.
- Predicate mapping to VidOR:
  - **Direct:** holding→hold, carrying→carry, touching→touch,
    leaning_on→lean_on, in_front_of, behind, above, beneath,
    on_the_side_of→next_to, in→inside, looking_at→watch.
  - **No equivalent:** sitting_on, standing_on, lying_on, wearing, eating,
    drinking_from, wiping, writing_on, twisting, covered_by,
    have_it_on_the_back.
  - **Not relations:** not_looking_at, not_contacting, unsure.
- Objects such as book, paper/notebook, door, and bed have no VidOR class.
  Adding them needs a new label-map version and retraining.
- **Leakage risk:** Charades-STA uses Charades videos. Train only on Charades
  train-split IDs, and assert zero overlap with Charades-STA and NA-VMR test videos.

## 6. Evaluation-only datasets, benchmark design, and safeguards

| Dataset | Access and size | Fit with VidQuery |
|---|---|---|
| Charades-STA | Needs Charades videos (16.3 GB); test queries over Charades test videos | Indoor activity queries; parser vocabulary will miss many phrasings. About 5 h to index the test videos [estimate at the measured 0.48x real time] |
| QVHighlights | Raw videos about 135-145 GB; validation 1,550 queries over 1,519 videos; CC BY-NC-SA | Free-text queries; mostly semantic and transcript evidence |
| NA-VMR negatives (*Moment of Untruth*, WACV 2025) | Built on **QVHighlights and Charades-STA** (ActivityNet only in the supplement) | Directly tests abstention, the project's research claim. Highest priority after a lecture set |
| TVR | 108,965 queries / 21,793 videos; 3 fps frames (43 GB) by form, about a week's wait; subtitles free | Frames only: needs an image-sequence adapter and subtitle ingestion. Lowest priority |

**Implemented now:** `evaluation/queries_challenge_ava_holdout.json`. It is
video-split (calibration = GNN validation videos, test = GNN test videos),
committed before any retrieval, and its builder fails on any overlap with
checkpoint training splits. It has 20 queries per video, 25% negative.

**Required safeguards for new datasets:**

- Keep an evaluation-only registry of video IDs.
- Every training builder asserts zero intersection with that registry.
- Never index the four AVA training videos (or `0f39OWEqJ24`) already in the
  main library for any reported result. They carry ground-truth relations.

Metric definitions are in [EVALUATION_END_TO_END.md](EVALUATION_END_TO_END.md).

## 8. Recommended strategy and trade-offs

Ranked by impact per effort:

1. **Parser coverage of natural action phrasings.** This is the largest
   measured effect (P@1 0.04 vs 0.33), takes hours, and costs nothing.
   Validate on calibration; report on a new test set, because these failures
   were seen on test.
2. **Lecture benchmark.** Label 5-10 real lectures in the Annotate tab, with
   Whisper `small` or `turbo` and phonetic matching measured on and off. This
   is the deployment setting the README claims; it takes one or two days of
   labelling.
3. **Environment fixes.** Point `SENTENCE_EMBEDDING_CACHE_DIR` at the cached
   MiniLM, document the working Python, and disable Neo4j or start it.
   Minutes.
4. **Calibration design.** Fit priors on top-1 answers, or re-fit thresholds,
   on calibration only. Make AURC/AUROC the headline. Hours.
5. **Retrain the action GNN without `annotation_only`/`detector_confidence`**,
   on the full AVA set with slim shards. One or two days on the laptop, about
   ₹0, expected +1-3 mAP.
6. **Full VidOR with corrected class mapping.** Half a day, about ₹0.
7. **Defer AVA-Kinetics and Action Genome** unless action or relation quality
   becomes the paper's claim.
