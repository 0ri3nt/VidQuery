## Benchmark

`evaluation/queries_challenge_ava_holdout.json`, built by
`scripts/build_ava_holdout_benchmark.py` from the official AVA v2.2 CSVs and
committed before any retrieval was run.

- **Videos.** The annotated 15-minute window (source 900-1800 s) of six AVA
  videos. Calibration: the action GNN's frozen validation videos
  `0f39OWEqJ24`, `9mLYmkonWZQ`, `covMYDBa5dk`. Test: its frozen test videos
  `hbYvDvJrpNk`, `t0V4drbYDnc`, `zR725veL-DI`. The builder fails if any of them
  appears in the training split of the v5 or v6 checkpoints (it found none).
- **Queries.** 20 per video, 120 in total: 15 positives and 5 in-domain
  negatives (25%). Positives are AVA labels present on 3+ keyframes but at most
  25% of the window; negatives are labels absent from the video's whole
  annotation, with synonyms of present labels excluded.
- **Ground truth.** Every run of consecutive labelled keyframes, as
  `[first - 0.5 s, last + 0.5 s]` with the peak at the run's middle.
- **Wording.** One fixed examiner-style phrase per label ("someone answering
  the phone"), written without consulting the parser.

## Metric definitions

All metrics are per query, averaged over queries, with 95% percentile bootstrap
intervals over queries (2,000 resamples, seed 2026).

- **P@1**: the top result overlaps a relevant interval or its time point is
  within 2 s of a peak. Positives only.
- **Recall@5**: fraction of a query's relevant intervals hit by any of the top 5.
- **Coverage / selective risk**: fraction of all queries answered (not
  abstained), and the error rate among answered queries. Answering a negative
  at all is an error.
- **AURC**: rank every query by fused confidence and answer the top *k*, for
  *k* = 1..N. AURC is the mean risk along that curve (lower is better). It
  measures whether confidence separates right from wrong answers, independently
  of the abstention threshold. It is undefined for Review-1 variants, which
  emit no confidence.
- **Rejection F1**: abstention treated as a detector of negative queries.
- **Answerability AUROC**: probability that a random positive query gets a
  higher confidence than a random negative query. 0.5 is chance.

**Evaluator fix.** Before this change, a `weak` answer to a negative query
counted as correct in the risk-coverage curve. On the default-priors test run,
the old rule scored all 15 negatives as not wrong although only 3 were
rejected, and reported AURC 0.4714 instead of 0.7217.

### What the test split supports

- End-to-end P@1 on action queries is about **0.13-0.20**, not 0.96 or 0.50.
  With 45 positives, the three systems' intervals overlap, so no system is
  significantly better at P@1.
- With hand-picked priors the abstention layer changes nothing here: no test
  query had all results `insufficient`, and 12 of 15 negatives got a `weak`
  answer.
- Learned priors move the operating point. Negative rejection rises from 0.20
  to 0.87 and selective risk falls from 0.865 to 0.692. The cost is answering
  only 24% of answerable queries (22% of all queries). On 22% of answerable
  queries it abstained even though a correct moment was among its results.
- Learned priors do **not** improve confidence ranking: AURC 0.768 vs 0.722 and
  AUROC 0.555 vs 0.507, with overlapping intervals. Both AUROCs are near
  chance. The claim "learned reliability reduces confident-wrong answers at
  equal coverage" is **not supported** by this benchmark.

## Bottlenecks (diagnosed after the single test run)

1. **Query parsing.** For 27 of 45 test positives the parser did not extract
   the intended AVA label ("kneeling down", "lying down", "running",
   "answering the phone", "working on a computer"). Those queries reached P@1
   0.037; the 18 parsed correctly reached 0.333. Leftover words such as
   "something" become spoken terms and match transcript noise.
2. **Action GNN.** Even when parsing is correct, P@1 is 0.33. The GNN emits
   actions on 179 of 180 segments per video, so action evidence is dense and
   weakly discriminative. Its held-out macro F1 is 0.072.
3. **Calibration base rate.** Priors are fitted on every top-20 result, most of
   which are wrong, so every learned prior falls to 0.06-0.24. The fixed
   thresholds (0.45/0.15) then make the system abstain far more often.
   Re-fitting thresholds on calibration, or fitting on top-1 results, are the
   obvious next calibration choices. Either must be decided on calibration only.

Parser fixes should be validated on calibration and reported on a **new** test
set, because the failures above were seen on this test split.

`RELIABILITY_PRIORS_PATH`.

## Limitations

- Movie footage, not lectures or classrooms. Speech, OCR, speaker, and
  ambiguity queries are not covered; they need human-labelled lecture
  recordings (Annotate tab).
- Queries were written by the benchmark author, not by independent examiners.
- AVA records at most three object and three person interactions per person,
  so negatives are near-exhaustive rather than guaranteed.
- Six videos give wide intervals. Treat differences under about 0.15 in P@1 as
  noise.

## Reproduce

Requires the six source videos in `data/ava/videos/` and the full model stack
(the system Python 3.12 install on the development laptop). The isolated index
keeps the main library untouched.

```bash
# 1. Cut the annotated windows (about 5 min).
for f in 0f39OWEqJ24.mp4 9mLYmkonWZQ.mkv covMYDBa5dk.mp4 hbYvDvJrpNk.mp4 t0V4drbYDnc.mkv zR725veL-DI.mkv; do
  id=${f%.*}
  ffmpeg -ss 900 -i data/ava/videos/$f -t 900 -c:v libx264 -preset veryfast -crf 23 \
    -pix_fmt yuv420p -c:a aac -b:a 128k data/app/benchmark/clips/ava_${id}_w900.mp4
done

# 2. Isolated index settings. The MiniLM cache path must point at a real cache.
export DATABASE_PATH=data/app/benchmark/benchmark.sqlite3
export UPLOAD_DIR=data/app/benchmark/uploads GENERATED_DIR=data/app/benchmark/generated
export ENABLE_NEO4J=false SENTENCE_EMBEDDING_CACHE_DIR=~/.cache/huggingface/hub

# 3. Index with models only (about 43 min on an RTX 4060 laptop).
for clip in data/app/benchmark/clips/*.mp4; do python -m vidquery process --video "$clip"; done

# 4. Calibrate on the calibration split only, then fit.
python -m scripts.calibrate_reliability --manifest evaluation/queries_challenge_ava_holdout.json \
  --split calibration --output evaluation/results/ava-holdout-reliability-calibration.json
python -m scripts.fit_reliability evaluation/results/ava-holdout-reliability-calibration.json \
  --output evaluation/results/ava-holdout-reliability-priors.json

# 5. Held-out test, once per prior set (each run includes the no-abstention ablation).
python -m vidquery evaluate-challenge --dataset evaluation/queries_challenge_ava_holdout.json \
  --split test --reliability-priors default --output evaluation/results/ava-holdout-test-default-priors.json
RELIABILITY_PRIORS_PATH=evaluation/results/ava-holdout-reliability-priors.json \
python -m vidquery evaluate-challenge --dataset evaluation/queries_challenge_ava_holdout.json \
  --split test --output evaluation/results/ava-holdout-test-learned-priors.json
```
